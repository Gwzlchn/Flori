# Flori 范围

本文件是产品范围的唯一权威:做什么、不做什么、什么条件下重新考虑。接口与文件格式见 [contracts.md](contracts.md),开发约定见 [CLAUDE.md](../CLAUDE.md)。

## 定位

Flori 是单人自用的学习笔记生成器:把想学的 B站、YouTube 视频和 arXiv 论文变成归自己所有的 Markdown 笔记。它只保证三件事:摄入可靠,笔记易读,文件归你。

## 对象

- 来源:平台加平台内的 ID,不单独建表。
- 任务:对一个来源的一次加工,是过程,不是内容。
- 笔记:成功的任务发布到 vault 的一个自包含文件夹。网页以笔记为主语,任务只在"处理过程"里出现。
- 领域:一级分类,必选,对应 vault 第一级文件夹。
- 集合:领域内的专题或一个订阅来源,可空,对应第二级文件夹。订阅是集合的属性。

分类只有领域和集合两级。平台同时就是内容类型,不另设类型、标签、风格、主题等维度。

## 数据分三层

| 层 | 内容 | 性质 |
|---|---|---|
| vault 的 Markdown 与图片 | 笔记、转写、原文、译文 | 知识的真相。发布后归用户,服务端不改不删 |
| SQLite | 领域、集合、订阅、任务与步骤状态 | 任务侧的唯一结构化真相 |
| 派生物 | 网页上的书架、计数、使用统计 | 随时可由前两层重算,不单独存 |

判断一项功能放在哪层,用一句话自检:删掉 SQLite,这项知识还在不在。网页不产生只存在于网页的知识。

## 开放性

- vault 目录本身就是导出物:不运行 Flori,用任何 Markdown 工具都能读全。
- 每篇笔记的 frontmatter 自带来源、领域、集合和生成它的任务,不查库也能知道它从哪来。
- 正文只用 CommonMark、GFM 表格、脚注和 `$` 公式,图片与文件间链接一律相对路径;Obsidian 私有语法只有折叠引用块。
- 发布后用户可以随意改笔记,服务端不读回也不覆盖。

## 网页与 Obsidian 的分工

| 网页 | Obsidian |
|---|---|
| 投递链接,手动订阅 | 阅读与编辑 |
| 按领域和集合列出已发布的笔记 | 全文搜索、标签、双链 |
| 预览笔记、原文、译文、转写,播放视频,点时间戳跳转 | 阅读状态、复习插件 |
| 处理过程:步骤、日志、AI 调用的原始输入输出 | 自己写的笔记 |
| 关于与系统:只读 | |

## 不做

| 不做 | 原因 | 重新考虑的条件 |
|---|---|---|
| PDF、网页文章、音频、本地视频 | 每种来源都是一条要长期维护的抓取与转换链 | 某一种来源连续一个月每周都想投而投不了 |
| 站内搜索 | Obsidian 搜索已覆盖,网页再做一份是两处真相 | 笔记满 100 篇,且常在没有 Obsidian 的设备上找笔记 |
| 标签、阅读状态、评分的网页管理 | 这些属于笔记本身,在 Obsidian 里改 | 不重新考虑 |
| 术语与概念库、知识图谱、主题页 | 需要人工审阅队列,笔记少时跨篇关联很稀 | 同一领域满 30 篇,且手工加的双链已经常用 |
| 站内问答、周报 | 外部 agent 直接读 vault 目录就能做 | 不重新考虑 |
| SRS 与复习排期 | 调度交给 Obsidian 的复习插件 | 不重新考虑;笔记末尾自测题见下 |
| MCP | vault 是普通目录,agent 不需要专门协议 | 不重新考虑 |
| AI 评审打分 | 分数不驱动任何动作 | 不重新考虑 |
| 可编辑的设置页、提示词在线编辑 | 配置只走环境变量,提示词随代码走 | 不重新考虑 |
| 多 worker、定时订阅、声明式流水线 | 两条固定流水线、单机单人用不上 | 扩大范围先问用户 |
| 导出命令、静态站生成 | vault 目录已经是导出物 | 想公开分享笔记时 |
| vault 备份与快照 | 用户改动丢失可接受,机器生成的部分可由任务目录重建 | 开始在 vault 里写不可重建的内容 |

## 有信号再做

- 笔记末尾的自测题:折叠,与笔记同一次 AI 调用产出。条件:真实读过十篇以上,觉得读完就忘。先在两三篇上试,题目质量不行就删掉提示词。
- 删除未发布的失败或取消任务:它们占着去重位。条件:第一次遇到重投被拒。

## 准入

加功能前按顺序问三句:

1. vault 加 Obsidian 加外部 agent 能不能做到?能,就只改提示词或写说明。
2. 不能时,有没有两周的手工使用记录证明需要?没有就不做。
3. 做的话,它的删除条件是什么?写不出来就不做。

SQLite 只存任务侧状态,固定四张表:domains、collections、jobs、steps。新增表先问用户。新增列只为列表与筛选服务;能从 job 目录或 vault 现算的不存。

其余总量约束见 CLAUDE.md 的架构一节;使用门见 CLAUDE.md 的产品一节。
